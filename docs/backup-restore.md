# 备份恢复事务与启动恢复

## 适用范围

从 1.16.1（77）起，`restore(from:)` 用持久化事务替换 `files/`、`HomeworkFiles/` 和索引。备份包格式仍为版本 1，资料库格式仍为 9，继续兼容既有旧格式备份。外部引用和挂载的作业目录仍只保存路径，不移动外部文件。

此前 `24efb2d` 的恢复只在内存中记录已移动目录，普通错误可以回滚，进程退出后无法重建回滚进度；在本轮起点 `8b3d1c8` 复核时问题仍存在。

## 阶段与提交点

恢复持有现有资料库独占锁和递归状态锁。开始前先完成现有 physical-storage、material-relocation 日志恢复和文件系统对账。

| 阶段 | 磁盘行为 | 中断后处理 |
| --- | --- | --- |
| 准备（日志发布前） | 复制备份到 `.restore-<UUID>/`；在隔离暂存库完成旧格式迁移；准备旧索引副本 | 正式目录和索引未替换；不自动删除无法归属的孤立暂存目录 |
| `prepared` | 原子写入并同步 `.backup-restore.json`，记录事务 UUID、限定路径、阶段、目录身份及新旧索引身份和 SHA-256 | 根据身份和实际位置回滚 |
| `movingOld` | 将旧索引副本归档到 `History/Restore-<UUID>/`，把旧目录移入同一恢复目录 | 旧目录可位于正式位置或 History，按身份归位 |
| `installing` | 逐一装入已准备完整的新目录；备份自带 History 放入恢复目录的 `BackupHistory/` | 新目录退回暂存区，再恢复旧目录 |
| `committing` | 沿用普通保存的 `.bak` 更新和原子索引替换机制 | **以新索引原子重命名到 `library.json` 为唯一提交点** |
| `committed` | 保留新资料库与旧 History 副本，清理暂存目录和旧文件观察缓存 | 完成清理，不回滚已提交的新索引 |
| `rollingBack` → `rolledBack` | 先让旧目录完整归位，再删除弃用的新暂存内容和本次未成功的 History 副本 | 可以重复回滚及继续部分完成的清理 |

日志不单独决定操作是否完成。每个根目录记录设备号、inode 和创建时间；重放检查旧目录在正式位置还是 History、新目录在暂存区还是正式位置。目录重命名完成但下一条阶段记录还未写入时，也能找到正确版本。移动使用同卷 `RENAME_EXCL`，不覆盖同名对象。

索引记录文件身份和内容摘要。新索引在暂存区同步后，其身份记录在日志中，原子重命名保留该身份。即使恢复的是完全相同的 JSON、文件内容却不同，也能区分提交前后。历史旧索引副本用摘要校验；关键受管理文件在清理前必须存在。

终态先持久化，再进行可重复的清理。重放自身在移动旧目录、移回新目录或部分清理后再次退出，下次打开仍能继续。成功恢复只生成一个本次 History 副本；回滚完成不留下一个假成功的副本。已有 History 内容始终保留。

## 启动顺序与其他日志

启动取得独占锁后，先处理 `.backup-restore.json`，再加载索引、补建目录、处理 `.physical-storage.jsonl` 与 `.material-relocation.json`，最后加载文件观察缓存和执行 Finder 对账。中间状态不会先被识别成用户移动或删除了文件。

恢复备份所需的格式迁移在暂存库内完成，迁移日志不会作用于正式目录；发布恢复日志前会清空正式库已有的可恢复文件事务。如果正式库同时存在恢复日志和其他文件事务日志，无法证明事务归属，打开会停止并保留两者，避免猜测顺序后移动或清理错误文件。同一实例发生无法完成的恢复后，其他文件事务也会拒绝继续，要求关闭并重新打开资料库。

提交后清除旧的 `.file-observations.json`，对选定的新目录重新建立观察，避免把旧 inode 信息套用到恢复的文件上。回滚不丢弃旧观察记录。

## 无法自动恢复时

损坏或未知版本日志、越界路径、符号链接、目录身份不匹配、缺失关键索引或文件、意外同名占用都会停止自动处理。错误包含资料库路径及问题说明；日志和恢复副本保留。

1. 正常退出课屿，先复制整个资料库到另一个位置。
2. 保留 `.backup-restore.json`、对应 `.restore-<UUID>/` 和 `History/Restore-<UUID>/`；不要仅删除日志以强行打开。
3. 按错误提示检查是否移动了恢复目录、替换了文件或改变了访问权限；能确认原因时，保留现场副本后，在原资料库中还原正确位置或权限，再重试打开。
4. 若不能确定哪一版本完整，保留现场供排查，或在另一个新建资料库中恢复一份已验证的备份。不要将不明来源的索引和目录拼接使用。

事务日志绑定原文件身份。整个资料库的复制品用于保全现场，不能直接替代原资料库续跑未完成事务；复制或跨卷迁移改变 inode 时，重放会拒绝猜测。需要换位置时，应先在原资料库完成恢复，或将确认完整的备份恢复到一个新建资料库。

日志发布前被终止可能留下孤立的 `.restore-*` 暂存区，但不会替换正式目录。不能仅凭名称自动删除它；确认没有对应事务、资料库可正常打开并已另行备份后，再人工处理。

## 验证方法与边界

所有故障夹具位于独立临时目录，未对真实用户资料库执行恢复或故障注入。`BackupRestoreRecoveryTests` 启动独立 Swift Testing 子进程，在指定边界写出握手文件并 `SIGSTOP`，父进程发送 `SIGKILL`，确认退出信号后重新打开资料库；不会依赖子进程的 `catch`、`defer` 或析构完成回滚。注入回调为内部测试入口，应用不读取故障注入环境变量。

覆盖：

- 日志刚发布、History 刚归档、旧目录部分／全部移走。
- 新目录部分／全部装入，索引尚未提交。
- 索引已提交、阶段日志未更新，以及提交后清理未完成。
- 自动回滚在每个目录逆操作后再次被终止。
- 自动清理在删除部分暂存内容、删除暂存根目录和清理未成功的 History 后再次被终止。
- 新旧索引内容完全相同但文件字节不同；旧格式备份先在暂存库完成物理迁移。
- 原子索引保存失败、普通异常、可恢复的提交后清理异常。
- 无效日志、路径越界、符号链接、缺失文件、路径占用、重叠文件事务日志。

每次正常恢复后连续打开三次，核对完整索引、文件字节和目录、资料 ID、课程与文件夹关联、计划附件、未索引文件、作业、空目录和 History 副本。失败场景重复打开并比较现场和外部目录，确认不会修改。

```sh
./scripts/test-macos.sh --filter 'BackupRestoreRecoveryTests|LibraryRepositoryTests|PhysicalFolderTests|MaterialStorageTests|HomeworkStorageTests|FileSystemSyncTests|MaterialOrganizationTests'
./scripts/test-macos.sh
./scripts/build-macos.sh
```

本轮实际结果另见 [README 的开发与验证](../README.md#开发与验证)，历史结果见 [历史记录](validation-history.md)。本测试验证真实**进程终止**；未模拟整机断电、存储硬件故障或网络文件系统的异常原子性，也未证明恶意外部进程持续并发改写目录时的安全性。资料库锁约束课屿写入者，不能锁住 Finder 或任意第三方写入者。
